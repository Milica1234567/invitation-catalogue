# RSVP setup

1. Open `src/rsvp/config.ts` and paste your deployed public HTTPS Apps Script `/exec` URL into the appropriate invitation entry. Keep `mode: "no-cors"` for direct Apps Script tests. All 11 invitations have independent endpoint fields in this one file: `invitation1.endpoint` through `invitation11.endpoint`. Paste a different deployed Apps Script URL for each invitation. The older endpoint fields in invitation data files are no longer used. Empty settings show a configuration error. No endpoint was provided, so the empty settings remain for you to fill.
2. Apps Script should execute as its owner and allow anonymous guests (Anyone), as allowed by your account. Use `/exec`, not `/dev` or a Sheet sharing URL. Parse `JSON.parse(e.postData.contents)` in doPost: the request contains JSON with Content-Type `text/plain;charset=UTF-8`. Keep all Google credentials and Sheet access server-side; only the public submission URL belongs in frontend code. Repeat input validation on the server.
3. From `catalogue`, run `npm install` if needed, then `npm run dev`. Open Vite's local URL and navigate to an invitation. Routes are `/invitation-catalogue/ana-marko` (1), `/invitation-catalogue/jovana-nikola` (2), `/invitation-catalogue/jelena-nikola` (3), and `/invitation-catalogue/invitation4` through `invitation11`.
4. Submit a unique test name. In DevTools > Network inspect the POST payload: fullName (string), attending (boolean), attendeeCount (number), note (string), submissionId (UUID). Declining always sends count 0. Invitation 9 appends its email, additional guests, meal and allergies to note so these existing fields are retained. Names must be nonblank and at most 120 characters; attending counts must be integers 1–5 (each form retains its own existing options); notes, including extra fields, are limited to 2000 characters. Existing HTML validation also checks email and required fields.
5. **Verify the row in your private Google Sheet**, matching the test name and submissionId (store that ID in your sheet), and check the count and attendance. Inspect Apps Script > Executions for failures. The no-cors result is opaque even if the server returned an error or redirected to sign-in; the form therefore says delivery is unverified and retains entered values. Neither that message nor Network status proves saving.
6. Test invalid/whitespace names, missing attendance, invalid email, long notes, declines, offline mode, retries and rapid double clicks. Only one request runs at once. Identical normalized values reuse their ID for the current mounted form, including after editing and restoring them; different values get a new ID. IDs are kept in memory, so refresh/navigation starts a new submission. No automatic retries occur. A request times out after 20 seconds; the server may still have saved it. Before retrying, check with the host. Server-side deduplication by submissionId (ideally atomic with Apps Script LockService) is needed to avoid duplicate rows after uncertain delivery; keeping the ID alone does not deduplicate.
7. Run `npm run build`, then your existing `npm run deploy` workflow. URL settings are bundled during build; rebuild and redeploy after changing them. On GitHub Pages, navigate from the catalogue to the invitation and submit a distinct test name, then verify its row in Sheets again. Test incognito to catch Google sign-in requirements, both attendance choices, double clicks and retries. Existing routes and deployment settings are unchanged.

## Reliable acknowledgements

For definitive guest-facing success, use a proxy API you control or another integration with readable acknowledgements. It must allow the frontend origin via CORS, forward the request, verify the write, and return HTTP 2xx JSON `{ "ok": true, "submissionId": "<same UUID>" }` only after saving. Configure its HTTPS endpoint with `mode: "cors"`. The utility requires both `ok: true` and the matching ID; HTTP 200 alone is insufficient. No proxy, database or paid service is included. Never automatically fall back from cors to no-cors: the first request might already have saved data.

References: [MDN Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch), [Apps Script web apps](https://developers.google.com/apps-script/guides/web), [Content Service redirects](https://developers.google.com/apps-script/guides/content).
